# B-ADV-0048 · Entrega de la intervención de cierre

El bloqueo técnico sigue describiendo el estado del cierre. Como ocurre con un bloqueo para el especificador, el selector puede despachar un paso concreto para atenderlo. En este caso selecciona el `bug-fix` existente. El agente recibe la intervención de la solicitud activa y su condición de salida. La reserva, la espera y la reanudación usan el circuito de ese paso. Si la llamada devuelve el mismo impedimento, el cierre sigue bloqueado.

- El lector de declaraciones formales admite el encabezado propio «Veredicto formal». Conserva el filtrado de citas y ejemplos para sus consumidores de revisión, preflight y métricas.
- Un dictamen técnico nuevo puede identificar explícitamente a Artemisa como agente. Para datos anteriores, el último enrutado y la revisión C1 rechazada deben acreditar la misma solicitud y el destino de resolución técnico. El nombre libre del responsable sirve para informar. Una evidencia ausente o ambigua conserva el bloqueo.
- La decisión se consulta solo para bugs de cierre bloqueados por intervención técnica. El historial identifica el grupo activo y su solicitud. El registro normal del paso acredita la atención de esa solicitud cuando la ejecución terminó con éxito técnico y sin revisión o cuota pendiente. Las esperas y las consultas de estado son reanudables. El contador del grupo, las pruebas, los commits de producto y el historial de rechazos conservan su identidad.
- En el cierre automático y al relanzar se usa la misma comprobación de elegibilidad. La consulta de estado es de solo lectura. La asignación devuelve al selector de tareas después de acreditar su atención. El caso terminal sin agente de B-ADV-0036 sigue vigente.
- Se verifican el paso principal, la reserva de Hades y el aviso de cuota con proveedores simulados en un repositorio Git aislado. Los artefactos del commit de Afinn permiten repetir el mismo recorrido histórico sin depender de sus datos en CI.
